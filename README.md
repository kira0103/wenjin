# 问津 Wenjin

文献阅读、历史研究、古籍点校与论文投稿工作台。版本号以 [package.json](package.json) 为准，代码统一维护在 `main`。

**日常使用看这一份；安装、部署、开发和备份看 [维护手册](docs/MAINTENANCE.md)。项目只维护这两份文档。**

最后核对：2026-10-31。以下命令在项目根目录的 PowerShell 7 中执行；当前本机目录为 `E:\写作软件`。

## 选择启动方式

| 你要做什么 | 启动方式 | 页面与数据 |
| --- | --- | --- |
| 使用 Windows 桌面客户端 | [桌面版](#桌面版)：先 `npm start`，再 `npm run dev` | 连接后台，用与 Web 相同的账号登录 |
| 一键启动后台和 Web 页面 | [Web 门户](#web-门户)：`npm start` 或双击 [启动后台.cmd](启动后台.cmd) | 自动准备页面、数据库与任务服务，浏览器账号登录 |
| 使用 Electron 薄客户端 | [薄客户端](#薄客户端)：`npm run dev:client` | 与桌面入口相同，连接账号后台 |

本机已有依赖即可按下文启动，后台入口会自动检查页面和数据库运行时。全新克隆先完成 [首次安装](docs/MAINTENANCE.md#首次安装)。

## 桌面版

```powershell
npm run dev
```

先在另一个终端运行 `npm start`，再执行上面的命令。客户端默认连接 `http://127.0.0.1:8765/app/`，与 Web 使用同一账号、文献和项目；不再另外启动 Python、数据库或 Vite。后台未启动时显示连接页，可修改服务地址后重试。连接其他后台也可在启动前设置 `SHIXUE_PORTAL_URL`，只保存地址，不保存明文密码。

旧本机工作区保留在原目录（例如 `工作台数据/`），不会自动发布为系统文献。需要查看旧资料时用 `npm run dev:local` 打开旧本地模式；迁移入口见维护手册。

## Web 门户

**在项目目录运行一个命令，或直接双击 [启动后台.cmd](启动后台.cmd)：**

```powershell
npm start
```

首次自动创建管理员账号 **`admin / admin123`**，启动时不用输入密码。登录管理后台后，在 **“账号与安全”** 修改密码；已有管理员沿用原密码，重启不会恢复默认密码。页面有变化时自动构建，先开放登录页面，再在后台准备数据库、Worker 和最近使用的研究工作区；首次准备数据库运行时可能需要下载和构建，启动窗口会显示进度。

首次进入新账号需准备个人工作区；服务就绪后复用工作区与连接，后续访问无需重复初始化。程序会记住资料目录。默认新门户位于 `.local/portal-preview/`，已有的 `.local/portal-data/` 会自动识别复用；已有多个门户时需要首次明确选择。运行窗口保留即可，重复启动会提示使用已有服务。

| 地址 | 用途 |
| --- | --- |
| [管理员后台](http://127.0.0.1:8765/admin/) | 管理用户、公共资料、检索配置、助手与 Skill、模型和管理员密码 |
| [用户工作区](http://127.0.0.1:8765/app/) | 用管理员建立的账号登录，首次使用临时密码时修改密码 |
| [服务状态](http://127.0.0.1:8765/health) | 检查门户是否存活；返回 `ok: true` |

上表为默认地址，实际地址以启动窗口显示为准。关闭网页或退出登录后，后台任务继续运行。

本机使用 NVIDIA 显卡加速文献向量化时，运行一次 `npm run setup:gpu`。它在 `.local/gpu-runtime/` 安装并验证独立 GPU 运行时，复用已有模型，不修改 CPU 环境或显卡驱动；准备好后重新启动后台生效。管理员“向量模型”页可查看后台实际使用的 GPU／CPU；GPU 初始化失败会显示 CPU 回退原因。当前本机已完成安装并启用，无需再运行安装命令。已启用 GPU 的机器可再运行一次 `npm run setup:fp16`（先 `npm stop`，用完再 `npm start`）：它把已缓存的 E5 权重转换成半精度副本并对比 fp32 输出余弦，通过后后台自动使用，向量空间与已有索引不变，大文件向量化约快 1.3–1.8 倍；设置 `SHIXUE_EMBEDDING_FP16=0` 可回退原精度。默认自动切分优先结构／递归父子策略；“允许自动使用语义切分”按需开启，单篇手动选择语义策略仍会执行。


只检查页面和资料阅读可以先不配置模型。执行 AI 任务前，在启动服务的同一终端设置密钥，再到后台“模型服务”填写地址和名称：

```powershell
$env:SHIXUE_MODEL_API_KEY = Read-Host '模型 API Key' -MaskInput
```

密钥应在 `npm start` 前设置。更换密钥时先运行 `npm stop`，等停止完成后设置新密钥，再运行 `npm start`。

修改 Web 界面时，保持门户运行，在另一个终端执行 `npm run dev:web`，访问 [开发页面](http://127.0.0.1:5173/app/)。

## 薄客户端

先启动账号后台，再运行 `npm run dev:client`；它与 `npm run dev` 使用同一登录客户端。

`Local: http://127.0.0.1:5173/` 是 Vite **开发服务器**提示，只在开发页面或旧本机模式下使用。日常用户与管理员页面使用 8765；桌面登录客户端不需要 5173。源码修改后重启后台，入口会按需构建最新页面；热更新开发用 `npm run dev:web`。

独立个人服务的旧令牌客户端保留为 `npm run dev:personal-server`，部署见 [个人服务部署](docs/MAINTENANCE.md#个人服务部署)。

## 日常操作

Web 用户页与管理后台采用统一的界面样式。管理员在顶部切换浅色/深色外观；手机上通过左上角菜单打开管理导航。期刊管理使用独立的数据概览、筛选区和列表，中文期刊可在列表中编辑。

| 功能 | 入口与使用方式 |
| --- | --- |
| 文献、原件与分类 | “文献库”导入和阅读 PDF、Word、TXT、Markdown、HTML、CSV、PPTX、XLSX、扫描图片或目录；“系统文献库”由管理员维护，“我的文献库”可自行导入、分类，只有本人可见 |
| 项目研究与点校 | 在项目中选用文献，确定底本、参校本和页段；工作稿、任务和成果保存在当前研究空间 |
| 摘录与研究助手 | 选取原文并保留出处，用所选资料检索、问答和整理研究结果；AI 结果需要人工核验 |
| 论文与期刊 | “论文投稿管理”跟进写作、投稿、返修，查看“中文C刊库”和“英文期刊库” |
| 系统配置与个人设置 | 管理后台统一维护“检索配置”“助手与 Skill”和模型服务；桌面与 Web 用户管理外观、账号与安全 |

系统文献、原件、录文修订和索引全局共享；个人文献及其原件、索引仅所属账号可见。项目可选用这两类文献，选材、摘录、笔记、任务、成果和投稿记录按账号保存。管理员的系统文献入口不展示个人文献。公共录文更新后，历史摘录与固定任务输入快照继续保留。检索策略和已发布的助手、Skill 由后台统一提供，用户端可选择使用；修改或发布后供后续检索与新任务使用。

RAG 在后台按登录账号执行：关键词、向量、问题改写和上下文扩展都受同一数据库行级权限约束，只能读取“系统 + 本人”的文献。原件、录文与索引保存在后台；向量引擎为 PostgreSQL 的 pgvector。殆知阁使用专用原文／字形归一索引，迁入其既有索引不表示已完成全库向量化；向量索引需单独加工。

管理员进入“检索配置”：

- **文献加工**：默认展示已有系统文献。可按待向量化、已就绪、模型变更、加工中或失败筛选，单篇点击“加工入向量库”，勾选本页后可点击“全选所有匹配文献”跨页选中全部筛选结果，翻页保留选择，也可取消个别文献；再点“加工全部已选文献”。点击“全库入库”可直接提交整个系统库，不受题名、状态筛选和分页影响；默认跳过已就绪和已排队项。后台每次分发 50 份任务，支持取消本批剩余任务、失败重试；也可只加工本页选中的文献，每页显示 20／50／100 份，全选范围不受分页数量限制；不必重新上传。已有录文直接清洗、切分和向量化，仅有原件的先解析。顶部显示全部已提交文献的总进度、各批完成数和进度、成功／失败／排队数量与当前执行文献；每篇显示阶段、进度条、分块计数和排队位置，多原件可展开查看。进度在上次请求完成后间隔 2.5 秒自动刷新，翻页和筛选保留批次范围；读取失败会显示错误与重试按钮，不会一直停在加载提示；可取消和重试。系统文献库顶部也有“文献加工与向量化”入口。页面遇到断连、超时或后台异常时，会在右上角显示持续保留的异常提示；展开“错误详情”可查看状态、错误类型和排查编号，编号对应后台日志。读取失败可在页面重试，提交失败先核对任务结果再重提。整体进度中的“查看失败文献”可直达具体文献的失败原因与重试入口。系统库支持编辑：资料目录中选择分类后可“编辑分类名称”或移动文献分类；顶部“编辑文献书目”可搜索全部系统文献（含殆知阁）并编辑题名、作者、年代、类型。普通文献阅读后可“维护原文与版本”；核心古籍录文通过源更新维护。
- **入库与加工**：配置 OCR、清洗及自动／结构／语义／递归／固定长度／分隔符／父子切分。在“文献加工”点击每份文献的“切分策略”，可独立配置、预览并保存或重建索引；也可手工录入、批量处理、查看进度和取消／重试任务。
- **向量模型**：选择本地 MiniLM、中文 BGE Small、英文 BGE Base、多语言 E5，或通过兼容 Embeddings API 接入 BGE-M3、Qwen3、OpenAI、通义及自定义服务。配置输出维度、密钥、批次、超时与查询前缀，测试固定样本；本地模型可单独提交准备任务。页面按后台实际文件显示本地已存在、尚未下载、文件不完整或准备中，提供模型清单与手动刷新；每个模型可直接下载、取消、失败重试或校验，显示预计大小和任务阶段，下载不切换当前模型。接口模型标为外部服务。
- **Query 处理**：按需启用问题改写、多 Query 扩展或 HyDE；使用后台模型服务，额外调用计入研究任务预算。原句精确检索跳过改写；HyDE 文本仅用于向量召回，不作为证据。
- **参数配置、检索测试与评测记录**：设置检索方式、Top K、权重、阈值、重排和上下文；测试当前表单或已保存配置，查看改写后的 Query、原文命中与耗时。测试不保存配置、不生成综合回答；启用 Query 处理时仍会产生模型用量。

上传支持每份文件选择切分策略，未覆盖的使用本批次默认；“自动识别”按内容逐文档选择，记录采用方案、理由和质量提示。父子模式可选择语义或结构父块。语义预览仅使用后台缓存模型，模型不可用或超过计算上限时回退到递归切分并显示原因。

修改配置不会自动重写旧文献；保存文档策略后，可点击“保存并重建索引”应用。清洗只生成索引派生文本，原件与原始录文保留。PPTX 提取文本、XLSX 提取缓存值，不执行宏、公式或远程链接。

向量模型默认仍为本地 MiniLM 384 维。更换模型、维度、前缀或修订标识后，需在“文献加工”选择文献重建索引；旧索引保留，异模型向量不会混算。固定维度模型不能任意改维度，接口输出会实际校验。接口模式会把待向量化文本发送到所配置服务；连接测试只发送页面列明的固定句，可能产生接口用量。纯预览不调用外部嵌入服务。

期刊目录由后台统一提供。管理员在“期刊库管理”查看中英文目录、维护中文书目信息；用户可查询和单独收藏，投稿历史保持私有。当前沿用已有 CSV 与英文快照，暂不做数据加工或自动采集。英文目录读取 `backend/data/english_journals.json.gz`。这些真实数据文件保存在本机，不随 Git 提交；页面展示的是数据文件标记的版本，详见 [可选资料](docs/MAINTENANCE.md#可选资料)。

## 检查是否正常

1. 先启动后台，再打开桌面版登录，与 Web 查看相同项目，并在“论文投稿管理 → 英文期刊库”查询刊名或 ISSN。
2. Web 管理员建立两个测试账号，发布一份测试 TXT；两个账号都能阅读原件。
3. 账号 A 导入个人文献、建项目、选材和保存摘录；账号 B 看不到这些私人记录，两者都能阅读系统文献。
4. 配置模型后执行一个小任务；关闭网页再登录，仍能查看任务进度或结果。

常见问题：

| 现象 | 检查位置 |
| --- | --- |
| `npm run dev` 停在 `electron .`，没有窗口 | 在原终端按 `Ctrl+C`，再重新运行；客户端入口更新需重启 Electron，网页强刷不能替代 |
| `npm run dev` 打开 Windows 窗口 | 这是桌面入口；浏览器入口使用门户的 `/app/`、`/admin/` |
| 旧项目或资料不见了 | 查看当前资料目录、账号和运行方式；桌面工作区与新门户的数据分别保存 |
| 英文期刊标签存在，但提示数据缺失 | 核对本机的 `backend/data/english_journals.json.gz`；恢复文件后重启后端 |
| 页面更新了，但新接口报错 | 退出客户端、停止原开发命令后重新启动，让 Python 后端也加载新代码 |
| 5173 已占用 | 这是开发端口；日常运行 `npm start` 与 `npm run dev` 不需要此端口 |
| AI 任务无法执行 | 核对模型地址、名称、密钥和后台进程；检查门户后台的模型配置 |

## 停止与备份

退出桌面客户端只会关闭窗口，后台任务继续执行。迁移资料前正常停止后台。个人服务停止 API 和 Worker 后维护数据。完整备份需要数据库、原件和工作稿配套保存，不能只复制 SQLite。

一键启动的后台在运行窗口按 `Ctrl+C`，或在另一个终端执行：

```powershell
npm stop
```

停止命令会等待任务保存，并正常停止工作区与共享数据库；窗口关闭后遗留的工作区也可用它清理。手动部署的停机顺序、备份范围和旧资料迁入见 [备份与迁移](docs/MAINTENANCE.md#备份与迁移)。模型请求会把所选文本发给配置的服务商；账号库、密钥和研究资料按私有数据保管。
